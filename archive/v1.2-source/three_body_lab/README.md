`three_body_lab_v1_1.html`을 브라우저에서 여세요. HTML 하나에 UI·계산 엔진·실험 작업자가 포함되어 있습니다. 설치·서버·CDN·외부 이미지·폰트·네트워크 요청이 필요하지 않습니다. 소스 ZIP을 풀었다면 HTML은 최상위에 있습니다.

## 바로 실험하기

**정확성 확인:** `정삼각형 회전`을 고르고 `내장 기준시험`을 실행합니다. 정확한 원운동 해, 이전 Taylor 예제, 근사 8자 귀환, 입력·근접 안전장치를 점검합니다.

**계산법 비교:** `8자 궤도`, T = 6, `적분기 비교`를 실행합니다. Leapfrog·RK4의 간격 .02/.01, RK45 허용오차 1e-8/1e-10, Taylor 16을 더 엄격한 RK45 계산과 비교합니다. 이 기준값도 수치해이며 참값 인증은 아닙니다.

**초기조건 민감도:** `민감도 실험`, T = 20, δ = 1e-6으로 `민감도 검증`을 실행합니다. 원본과 섭동 복제를 기본/고정밀 설정으로 각각 계산하여 총 네 궤도를 비교합니다. 물체 A의 x를 δ만큼 옮긴 다음 전체 질량중심을 보존하도록 평행이동합니다.

**시간 가역성:** `시간 반전`은 T까지 진행한 뒤 모든 속도를 반전해 T만큼 더 진행합니다. 원래 상태로의 귀환 오차를 측정합니다. 작은 귀환 오차가 정확한 궤도를 보증하지는 않습니다.

**실패 관찰:** `이전 비대칭 예제` 또는 `극근접 스트레스`에서 큰 고정 간격을 사용하면 안전 중단이 일어날 수 있습니다. Δt를 줄이거나 적응형 RK45를 선택한 뒤 `변경사항 적용`으로 다시 시작하세요. 근접 통과를 누락한 채 그럴듯한 애니메이션을 계속하지 않도록 설계했습니다.

## 조작 및 저장

- 스페이스: 재생/정지, R: 리셋, F: 자동 화면 맞춤, 마침표: 관측 간격 .02 진행. 입력 상자에서는 타이핑을 우선합니다.
- 빈 공간 드래그: 화면 이동. 휠: 커서 중심 확대. 일시정지 후 물체 드래그: 현재 상태 전체를 새 초기조건으로 사용. Shift+물체 드래그: 속도 편집.
- 숫자와 계산 설정은 변경 후 `변경사항 적용`을 눌러야 반영되며 t = 0으로 돌아갑니다. 시각화 설정과 재생 배속은 적분 정확도를 직접 바꾸지 않습니다.
- `초기조건 저장`은 적용된 초기조건·질량·계산 설정·시드·섭동 설정을 JSON으로 저장합니다. 현재 재생 시점의 체크포인트는 아닙니다. `불러오기`는 t = 0부터 재현합니다.
- CSV는 최근 최대 6,000개 관측점(약 120 시간단위)과 원본 상태·에너지·각운동량·운동량 오차·질량중심 오차·근접 거리·분리도·질량·모델 설정을 저장합니다. 내부 적분 스텝을 모두 저장하지는 않습니다.
- 실험은 별도 Blob Worker에서 복제 상태로 계산합니다. 원본 재생은 일시정지되고 바뀌지 않습니다. 실험 중단 버튼으로 Worker를 종료할 수 있습니다.
- 최근 실험 12개는 현재 탭에서 유지됩니다. 실험 기록 JSON에는 재현 입력과 측정값이 들어갑니다. 기록 JSON은 초기조건 불러오기와는 다른 형식입니다. 탭을 닫기 전에 기록을 저장하세요.

## 물리와 수치적 범위

세 점질량의 **2D 평면 뉴턴 중력**입니다. G = 1인 무차원 단위를 사용합니다. 기본 연화 길이 ε = 0이며 중력은 원래의 1/r² 힘입니다. 화면 원의 크기는 물체의 물리 반지름이나 충돌 반지름이 아닙니다. 상대론, 유한 물체 충돌, 병합, 중력파 등은 포함하지 않습니다.

연화를 켜면 힘의 분모는 `(r² + ε²)^(3/2)`가 되고 퍼텐셜은 `-G mi mj / sqrt(r²+ε²)`가 됩니다. 이는 **수정된 물리 모델**이지 충돌 정칙화가 아닙니다. 에너지도 같은 연화 모델로 계산합니다.

RK45는 Dormand–Prince 5(4) 쌍을 사용합니다. Taylor 16은 이전 대화의 급수 재귀식을 옮겨 매 스텝 새로 전개하고, 위치 17차와 속도 16차 다항식을 평가합니다. 한 스텝과 두 반스텝 차이에서 오차를 추정하며 위치 다항식을 먼 미래에 한 번에 대입하지 않습니다. RK4와 kick-drift-kick Leapfrog는 고정 간격입니다. 목표 시각을 맞추기 위한 끝점 스텝은 짧아질 수 있습니다.

적응형 기본값: rtol = 1e-10, atol = 1e-12, hmax = .02. 국소 오차 및 근접 시간척도 제한을 함께 적용합니다. 근접 거리 1e-5와 최소 간격 1e-12는 이 실험실의 안전 정책이지 실제 천체 크기나 수학적 충돌 인증이 아닙니다. 두 물체의 진짜 충돌을 통과하는 정칙화와 임의정밀도 계산은 구현하지 않았습니다.

에너지 진단의 분모는 `E* = max(|E0|, 1e-12(K0+|U0|), 1e-30)`입니다. 각운동량이 처음에 0인 경우를 위해 `|ΔL|`은 상대 오차가 아니라 절대 변화로 표시합니다. 질량중심 오차는 원래 질량중심의 등속 이동을 기준으로 합니다.

이 구현은 표준 배정밀도 계산입니다. 수렴반경·전역 오차·충돌 없는 구간을 엄밀히 인증하지 않습니다. 에너지 보존, 가역성, 두 방법의 일치, 짧은 시험 통과만으로 모든 시간의 궤도 정확성이 보증되지 않습니다. 섭동 궤도의 분리는 Lyapunov 지수나 혼돈의 증명이 아닙니다. 일반해의 새 증명을 주장하지 않습니다.

## 파일 구성과 재실행

`physics.js`: 물리 및 적분 엔진. Node의 CommonJS와 브라우저 전역 모두 지원합니다.

`experiments.js`: 동일 엔진을 사용하는 내장 실험. 기준값과의 차이를 참값 오차라고 표시하지 않습니다.

`app.js`, `style.css`, `template.html`: UI와 단일 HTML 조립 원본.

`build.py`: 원본에서 최상위 `three_body_lab_v1_1.html`을 다시 생성합니다.

```sh
python three_body_lab/build.py
# 독립 수치 검산: Node, Python NumPy 및 SciPy 필요
python three_body_lab/test_numerics.py
# 브라우저 검산: Python Playwright와 Chromium 필요
python three_body_lab/test_browser.py
```

브라우저 테스트는 이 컨테이너의 Chromium 경로 `/usr/bin/chromium`을 사용합니다. 다른 기기에서는 설치한 Chromium 경로로 `executable_path`를 변경하세요. 시뮬레이터 자체에는 Python·Node·Playwright가 필요하지 않습니다.

직접 엔진을 사용한 예:

```js
const P = require('./three_body_lab/physics.js');
const p = P.preset('figure8');
const s = new P.Simulator(p.y, p.m, {method:'rk45', rtol:1e-11, atol:1e-13});
s.advanceTo(6);
console.log(s.y, s.measure(), s.stats);
```

상태 순서는 `[xA,yA,xB,yB,xC,yC,vxA,vyA,vxB,vyB,vxC,vyC]`입니다. 실험 기록을 새 조건과 함께 공유하면 같은 엔진으로 재현하며 다음 버전을 개선할 수 있습니다.
