## 2. 실제 실험에서 확인한 문제와 개선

### A. 고정 간격은 근접 통과에서 그럴듯하게 틀릴 수 있음

이전 비대칭 예제, 질량 (1,2,3), G = 1, ε = 0, T = 2를 사용했습니다.

| 계산 | 관측 최대 정규화 에너지 변화 | 결과 |
|---|---:|---|
| RK4, Δt = .02, 근접 안전장치 끔 | 0.5971390647 | 완료하지만 약 59.7% 변화 |
| RK4, Δt = .02, 안전장치 켬 | 1.4532e-5 (중단 전) | t ≈ .72에서 간격 부족을 알려 중단 |
| RK45, rtol = 1e-10 | 3.4331e-10 | T = 2 완료 |

그래서 기본을 적응형 RK45로 두고, 고정 간격이 근접 시간척도에 비해 크면 중단하도록 했습니다. 강제로 힘을 약하게 만들거나 궤도를 순간이동시켜 실패를 숨기지 않습니다. 연화는 기본값 0이며 사용자가 명시적으로 고를 때만 수정된 힘과 그에 맞는 퍼텐셜을 씁니다.

### B. 목표 시간 바로 앞에서의 잘못된 MIN_STEP 중단

초기 구현에서 T = 6, Δt = .02 또는 .01인 고정 간격 계산이 300/600 스텝 뒤 마지막 약 1e-14 수준의 **무차원 시간 잔차**를 새 스텝으로 처리하려 했습니다. 이 잔차는 실제 시간 단위로 환산한 값이 아니라 1e-14 정도의 부동소수점 덧셈 잔차입니다. 최소 간격 1e-12보다 작다는 이유로 `MIN_STEP` 중단을 내는 버그였습니다.

보정 합산으로 시간 누적을 바꾸고 끝점 비교를 일관되게 처리했습니다. 이후 T = 6의 고정 간격 비교와 시간 반전이 모두 정상 완료됐습니다. 최소 간격 안전장치를 무조건 끄는 방식으로 고친 것이 아닙니다.

### C. 낮은 에너지 오차나 작은 귀환 오차만으로 정확성을 선언하면 안 됨

정삼각형 정확해의 T = 2 시험에서 Leapfrog(Δt=.002)는 에너지 변화 약 6.3e-13이었지만 위치 RMS 차이는 약 3.876e-7이었습니다. 아래 8자 실험에서도 Leapfrog는 왕복 후 매우 잘 돌아오지만 끝점 위치는 고정밀 기준과 차이가 큽니다.

그래서 에너지·운동량 진단과 함께 정확해 검사, 적분 간격 비교, 별도의 시간 반전 검사를 분리했습니다.

### D. 편집 상태와 실행 상태 혼동 방지

새 수치를 타이핑해도 적용 전에는 원본 계산을 바꾸지 않습니다. 적용되지 않은 편집이 있을 때 드래그로 이를 덮어쓰지 않도록 보호했습니다. 잘못된 질량·JSON 불러오기는 기존 상태를 보존합니다. 초기조건 JSON은 체크포인트가 아니라 t = 0 재현 설정이라고 UI에 명시했습니다.

초기 위치 RMS 차이는 3.39955299e-07이며 최종 분리는 초기의 약 728.2배였습니다. δ 자체와 RMS 차이는 서로 다른 지표입니다. δ는 물체 A에 가한 x 편집량이고, RMS는 질량중심을 보존하도록 재조정한 세 물체의 여섯 위치 성분으로 계산합니다.

물체 A의 x를 δ만큼 이동한 뒤, 전체 질량중심이 변하지 않게 평행이동합니다. 기본·섭동 양쪽을 더 엄격한 허용오차로 재계산했습니다. 큰 분리는 이 시간 구간의 민감도를 뜻하며 양의 Lyapunov 지수나 혼돈의 수학적 증명은 아닙니다. 두 정밀도의 일치는 오차 상한도 아닙니다.

이 결과는 해당 유한 구간에서 초기조건 섭동의 효과가 두 정밀도 설정 간 차이보다 훨씬 컸다는 관측입니다. 양의 Lyapunov 지수·혼돈·무한 시간 불안정성을 증명한 것은 아닙니다.

## 6. 브라우저 검증 범위

실제 배포 HTML 바이트를 Chromium의 빈 문서에 넣고 조작했습니다. 이 컨테이너는 정책상 모든 URL 이동을 차단하므로 **`file://` 탐색 검증은 하지 못했습니다.** `about:blank`의 opaque origin에서 Blob Worker, 실제 초기조건 JSON/CSV 다운로드, 파일 입력, 네 종류 실험, 재생·정지, 근접 중단, 드래그, 반응형 화면을 확인했습니다. 외부 http/https 요청은 없었고 페이지 JavaScript 런타임 오류는 없었습니다.

1500×1000 기본 레이아웃을 시각 점검했고 1280×800, 900×900, 390×844에서 가로 넘침이 없는 것을 확인했습니다. macOS Safari/WebKit·실제 M5 하드웨어·macOS 전체화면은 검증하지 않았습니다. 개발 컨테이너의 브라우저 설치용 네트워크가 허용되지 않아 제공된 시스템 Chromium을 사용했습니다.

## 7. 남은 범위와 다음 개선 후보
